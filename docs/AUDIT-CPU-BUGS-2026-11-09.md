# Dimble 后台占用与使用问题分析（2026-11-09）

分支 `sync-upstream-0.3.5`。实测由主 Agent 完成；代码审查由两个 Sonnet 子 Agent 只读完成，主 Agent 逐条读代码核实后再改。

## 一、结论

- **CPU 不高。** 运行 72 分钟累计 CPU 22 秒，平均约 **0.5%**；静置时 5 秒采样 0%~2.4%；内存约 62–74MB。
- 开销是**事件触发的小爆发**（鼠标靠近菜单栏、展开/收起时读菜单栏结构和抓遮罩图），不是空闲时空转。上游作者已经做过一轮性能审查，大部分热路径本来就有缓存和节流。
- 本轮修掉了你截图的「放不下」误报、两个真实的使用问题，以及几处可以安全减少的后台唤醒。

## 三、核实后决定不改的

- **遮罩截图频率**（子 Agent 评为最高）：读代码后发现「靠近时重拍」本来就只在菜单栏背后真变了才触发，作者为准确性特意选了较慢的截图方式。限频的话，展开时就要现拍，截图次数不一定少，展开反而变慢。估算开销约 0.1% CPU，不值得冒这个风险。
- **鼠标移动监听**：上游已做过性能优化（同一窗口 250ms 内复用结果，菜单栏外只做加锁判断）。剩下的优化空间很小，降线程优先级可能让悬停变钝，所以没动。
- **「全仓计时器没设容差」**：核实后说法偏夸大。常驻的循环大多只在需要时才跑，媒体状态的 30 秒计时器已有 5 秒容差。只补了 SharePlay 一处，每日更新提醒的计时器可以忽略。
- **每次展开/收起读 2~3 次菜单栏结构**（引擎核心）：参数是作者实测调过的，改了容易出现图标错位。要改必须有实机反复测试，这轮不碰。

## 四、仍未处理

2. 「额外图标」功能开着时会常驻几个 `log stream` 子进程，CPU 记在系统名下。不用的额外图标建议在设置里关掉。
3. 悬停抑制的日志文案不准确（纯文字，不影响使用）。
4. AGENTS.md §7 里原有的已知问题，本轮没碰。

## 五、建议你实测的三件事

1. 用一阵子，看「放不下」是否还会错误地列出微信 / 专注模式。
2. 点面板里的 Clash Verge：主窗口打开后约 3 秒内菜单栏应恢复正常、能点。
3. 微信开着时，悬停或点菜单栏空白是否比以前更灵；如果还被拒，日志里搜 `band: click refused — on 微信`，看有没有带 `α` 的透明度。

不满意可回退：`scripts/dev-install.sh --rollback`（回到本轮之前的版本，备份在 `~/.agents/backups/apps/`）。
